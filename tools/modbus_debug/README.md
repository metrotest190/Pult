# Отладчик Modbus RTU для пульта разрывной машины

Инструмент для отладки прошивки пульта (`Pult_Encod_Koda`) без разрывной машины.
Работает как **Modbus RTU master** на COM-порту через USB-RS485 переходник.

## Параметры связи (из прошивки пульта)

| Параметр     | Значение                 |
|--------------|--------------------------|
| Протокол     | Modbus RTU               |
| Адрес slave  | 0x0A (10)                |
| Скорость     | 115200, 8N1              |
| Шина         | 4-проводная RS485 (RX/TX раздельные, переключение направления не нужно) |

## Карта регистров

**Holding (FC03/FC06/FC16):**
| Адрес      | Тип    | Назначение                          |
|------------|--------|-------------------------------------|
| 0x1000-01  | float  | перемещение (IEEE754, старшее слово первым) |
| 0x1002-03  | float  | сила                                |
| 0x1004-05  | float  | деформация                          |
| 0x1006-07  | float  | время испытания                     |
| 0x2000     | uint16 | значение дисплея (запись 0..30)     |
| 0x3000     | uint16 | диагностика TJC (чтение)            |
| 0x3001     | uint16 | флаг фиксации результата: 1 = зафиксирован (чтение) |
| 0x3002-03  | float  | максимум силы F при фиксации (чтение) |
| 0x3004-05  | float  | перемещение L в точке максимума F (чтение) |
| 0x3006-07  | float  | деформация D в точке максимума F (чтение) |
| 0x4002     | int16  | быстрая команда (0 = отпущена, ±5 как с кнопок) |

**Input (FC04):**
| Адрес  | Тип    | Назначение                          |
|--------|--------|-------------------------------------|
| 0x4000 | uint16 | порт A (кнопки, инвертированные по маске) |
| 0x4001 | uint16 | порт B (кнопки, инвертированные по маске) |
| 0x4002 | uint16 | энкодер (int8) или быстрая команда  |

Кнопки порта A: бит1=F2, бит2=F1, бит3=верх.захват-закрыть, бит8=нижн.захват-открыть,
бит11=возврат, бит12=запись нуля, бит15=стоп.
Кнопки порта B: бит3=нижн.захват-закрыть, бит8=защита, бит9=пуск, бит12=кнопка энкодера, бит15=верх.захват-открыть.

## Установка

```bash
python -m pip install pyserial
```

## Использование

```bash
# список COM-портов
python modbus_debug.py list-ports

# проверка связи + чтение 4 float-каналов
python modbus_debug.py --port COM12 ping

# чтение holding/input
python modbus_debug.py read holding 0x1000 8
python modbus_debug.py read input 0x4000 3

# запись float в канал (0=перемещение, 1=сила, 2=деформация, 3=время)
python modbus_debug.py write-float 1 123.45

# дисплей и быстрая команда
python modbus_debug.py display 5
python modbus_debug.py cmd 5
python modbus_debug.py cmd 0

# циклический опрос (таблица + лог в CSV)
python modbus_debug.py poll --interval 0.5 --log poll.csv

# сырые кадры: hex TX/RX + проверка CRC + RTT (для отладки стека)
python modbus_debug.py raw

# эмуляция машины: треугольник 0..100 (период 10 с = 5 с вверх + 5 с вниз),
# каждый следующий канал сдвинут на 1 с; считывает диагностику TJC (0x3000)
python modbus_debug.py emulate --interval 0.1 --period 10 --delay 1
# параметры: --amp 100 --period 10 --delay 1 (задержка канала i = delay*i с)

# автотест стека пульта (нужен подключённый пульт!)
python modbus_debug.py test

# самопроверка CRC/парсера без порта
python modbus_debug.py selftest
```

## Сценарные скрипты проверки пульта

Отдельные скрипты для проверки **логики пульта** (рост величин и фиксация
результата), а не только стека Modbus. Оба пишут все float-каналы
**одним кадром FC16** (0x1000 n=8), поэтому значения на экране не
рассинхронизируются между кадрами.

### `test_ldf.py` — рост L/D/F, спад F и проверка фиксации

Профиль: 0..`--rise` — L, D, F растут с разными скоростями; затем F убывает
с `--vFall`, а L и D продолжают расти. Пульт должен зафиксировать максимум F
и соответствующие L/D; скрипт сверяет зафиксированное с ожидаемым (±5%).

```bash
# обычный прогон: пик F = 100
python test_ldf.py --port COM13

# «тонкий материал»: пик F = 0.2 (проверка порога F_PEAK_MIN_FORCE)
python test_ldf.py --port COM13 --vF 0.04 --rise 5 --vFall 0.05 --vL 2 --vD 5
```

Параметры: `--vL --vD --vF` (скорости, ед/с), `--rise` (момент спада F, с),
`--vFall`, `--interval`, `--hold` (сколько держать результат на экране),
`--log` (CSV). Код выхода 0 — фиксация есть и значения совпали.

### `scenario_DLF.py` — тот же сценарий, но для визуальной проверки

Ровно тот тест, что виден глазами на экране пульта: три величины растут с
разной скоростью, через `--switch` секунд F разворачивается и падает, L и D
продолжают расти. Лога и сверки нет — только плавная картинка на дисплее.

```bash
python scenario_DLF.py --port COM13 --switch 5 --vL 3 --vD 1.5 --vF 6
python modbus_debug.py --port COM13 peak   # прочитать зафиксированный итог
```

Порты/адрес/скорость меняются глобальными флагами: `--port COM12 --addr 0x0A --baud 115200 --timeout 0.6`.

## Типичные сценарии

1. **«Пульт вообще отвечает?»** → `ping`
2. **Жму кнопку на пульте, приходит ли бит?** → `poll` (таблица кнопок обновляется)
3. **Стек FreeModbus ломает кадры/CRC** → `raw` (видно каждый байт TX/RX, проверка CRC, таймауты)
4. **Проверить графики/дисплей пульта без машины** → `emulate` (машина-эмулятор шлёт перемещение/силу/деформацию/время)
5. **Регрессия после правок прошивки** → `test` (9 проверок: чтение, запись с контролем, exception, битый CRC, чужой адрес, FC17)
6. **Фиксация L/D при максимуме силы** → `peak` (читает 0x3001-0x3007):
   ```bash
   python modbus_debug.py --port COM7 peak      # флаг + максимум F, L, D
   python modbus_debug.py --port COM7 write-float 1 100   # канал 1 = сила
   python modbus_debug.py --port COM7 write-float 1 20    # срыв -> фиксация
   python modbus_debug.py --port COM7 peak      # флаг = ЗАФИКСИРОВАН
   ```
   Сброс фиксации — нажатием **любой** кнопки на пульте (раньше сбрасывали
только «запись нуля» PA12 и «пуск» PB9). Поворот энкодера сброса не даёт.

## Известные ограничения прошивки пульта

- **Одиночный буфер кадра + FIFO событий (MBRTU-02).** FreeModbus хранит один
  RTU-кадр в `ucRTUBuf`. Если мастер шлёт **broadcast-запись** (адрес 0, ответа
  нет) и сразу — без паузы ≥ 1750 мкс — начинает следующий кадр, новый кадр
  может перезаписать буфер до обработки предыдущего `EV_EXECUTE` (окно — один
  проход главного цикла, микросекунды). Для обычного опроса с ответом гонка
  невозможна; риск только при broadcast-записях подряд. Мастеру рекомендуется
  держать паузу между broadcast-запросами не менее 2 мс.
- **T3.5 = 1750 мкс при 115200** (фиксированное значение Modbus для скоростей
  > 19200 бод, 35 × 50 мкс). Кадр считается завершённым после паузы в линии
  1750 мкс; межбайтовая пауза мастера должна быть меньше (обычно < 1.5 символа).
- **Coils/Discrete Inputs не реализованы**: запросы FC01/02/05/15 отвечают
  exception 0x02 (по замыслу).
- **Карта регистров фиксирована**: см. таблицу выше; float — IEEE754, старшее
  слово регистра первым; 0x2000 принимает только 0..30; 0x4002 — int16.
