# Анализ проекта экрана TJC `V1.4.1.HMI` и его связка с прошивкой STM32

**Файл:** `C:\Users\190\Desktop\Пульт\Большой\Screen\V1.4.1.HMI` (8 601 207 байт, редактор USART HMI)
**Генератор заголовков:** `V1.4.1.h` (от 24.06.2026, экспорт USART HMI)
**Прошивка:** проект `Pult_Encod_Koda` (STM32F103C8Tx, HAL, FreeModbus RTU, TJC по USART3)

> Метод: файл `.HMI` — это бинарный контейнер TJC. Заголовок `V1.4.1.HMI` в момент анализа был открыт в USART HMI, поэтому формат контейнера разобран на разблокированной копии `V1.4 .0.HMI` (тот же размер, та же структура), после чего скрипт `extract_hmi.ps1` извлёк из `V1.4.1.HMI` весь встроенный скрипт экрана (`Program.s`) в `hmi_script_dump_V141.txt`. Сопоставление с прошивкой выполнено по `main.c`, `portserial.c`, `tjc_usart_hmi.h`.

## 1. Что такое `V1.4.1.HMI`

Это **проект экрана TJC (淘晶驰 / USART HMI)**, а не прошивка экрана. Внутри — контейнер со встроенными файлами:

| Тип вложенного файла | Расширение | Содержимое |
|---|---|---|
| Скрипт экрана | `Program.s` | логика страниц, событий, команд `printh` |
| Изображения | `*.is` | PNG-картинки (кнопки, индикаторы) |
| Шрифты | `*.zi` | растровые шрифты |
| Фоны | `*.pa` | фоновые изображения страниц |

Структура контейнера: заголовок `9F 00 00 00` (у `V1.4 .0.HMI` — `9A 00 00 00`), таблица файлов (продублирована дважды — по смещению 0 и 0x80000), затем данные файлов. Строки скрипта хранятся как ASCII-текст с бинарными вставками (атрибуты компонентов — длина-префикс + имя + значение).

Сам экран: **TJC4832T135** (480×320, как у `TJC4832T135.HMI` в той же папке), UART 115200 8N1 — совпадает с конфигурацией `huart3` в прошивке:

```c
/* main.c:793-799 */
huart3.Init.BaudRate = 115200;
huart3.Init.WordLength = UART_WORDLENGTH_8B;
huart3.Init.StopBits = UART_STOPBITS_1;
huart3.Init.Parity = UART_PARITY_NONE;
```
Физика: PB10 = USART3_TX, PB11 = USART3_RX (`stm32f1xx_hal_msp.c:246-254`).

## 2. Страницы и объекты экрана (по `V1.4.1.h` + дампу скрипта)

Извлечённые из бинарника имена объектов совпадают с `V1.4.1.h` (сгенерированным из этого проекта):

| Страница (id) | Объекты (имя: индекс) | Назначение |
|---|---|---|
| **page0** (0) | `p0`, `t0` | Заставка/приветствие |
| **page1** (1) | `p6` (картинка-индикатор), `t1,t4,t5,t9,t0,t2,t3,t6,t7,t10,t11,t12` (тексты), `x0,x1,x2,x3` (прогресс-бары), `p0` | **Основной рабочий экран**: 4 значения в виде прогресс-баров, текстовые поля, крупный индикатор `p6` |
| **page2** (2) | `t0..t8`, `x4,x5,x6,x7` | Второй экран с ещё 4 прогресс-барами |
| **keybdB** (3) | `t0,t2`, `b0..b10` (цифры), `b200` (⌫), `b210` (очистка), `b249` (←), `b251` (→), `b99` (ввод/OK), `show`, `input`, `temp,temp2,tempstr`, `inputlenth`, `loadpageid`, `loadcmpid`, `tm0` | **Экранная клавиатура** для ввода чисел |
| **page3** (4) | `s0` (**кривая/осциллограф**, 3 канала), `x0,x1,x2` (бары), `t0,t1,t2,t3,t4,t6,t7` (тексты), `c0,c1,c2` (**чекбоксы видимости каналов**) | **Экран графиков** (трендов) |

Ключевые объекты для прошивки (используются в `main.c` **по имени**, а не по числовому id):

| Объект | Атрибут | Команда из прошивки | Назначение |
|---|---|---|---|
| `x0..x3` | `val` | `tjc_send_val("x0","val",...)` | прогресс-бары, сотые доли float |
| `t9` | `txt` | `tjc_send_txt("t9","txt",...)` | вывод значения (энкодер/дисплей) |
| `p6` | `pic` | `tjc_send_val("p6","pic",15..27)` | смена картинки-индикатора (кнопки/энкодер) |
| `s0` | каналы 0..2 | `add 1,<ch>,<val>` / `cle 1,<ch>` / `addt 1,<ch>,<count>` | кривая: добавление точки, очистка, пакетная передача |
| `c0,c1,c2` | `val` | приём `55 AA <ch> <state>` | чекбоксы видимости каналов графика |

## 3. Протокол обмена (USART3, 115200 8N1)

### 3.1 STM32 → экран (команды TJC, завершаются `FF FF FF`)

Формируются `tjc_send_string/tjc_send_txt/tjc_send_val/tjc_send_nstring` (`portserial.c:194-242`), буферизуются в двойном кольце `tjc_tx_buf_a/b` и отправляются через `tjc_flush_tx()` без busy-wait.

| Команда | Пример из `main.c` | Смысл |
|---|---|---|
| `obj.attr=value` + `FF FF FF` | `x0.val=12345` | запись значения в атрибут объекта |
| `obj.txt="..."` + `FF FF FF` | `t9.txt="123"` | запись текста |
| `p6.pic=15` | строка 1077 | смена картинки |
| `add 1,<ch>,<val>` + `FF FF FF` | строка 389 | добавить одну точку в канал кривой |
| `cle 1,<ch>` + `FF FF FF` | строка 319 | очистить канал кривой |
| `addt 1,<ch>,<count>` + `FF FF FF` | строка 424 | начать пакетную передачу кривой |
| сырые байты данных | строка 452-460 | массив точек канала (1 байт/точка) |

**Кривая `addt` (важно для `STATE_ADDT_*` в `main.c`):**
1. МК отправляет `cle 1,<ch>` — очистка канала;
2. МК отправляет `addt 1,<ch>,<count>` — запрос на приём `count` точек;
3. Экран отвечает **`0xFE`** — «готов принимать данные» (`tjc_addt_fe_received`);
4. МК отправляет `count` байт (значения канала, 1 байт = точка);
5. Экран отвечает **`0xFD`** — «данные приняты» (`tjc_addt_fd_received`), канал перерисовывается.

Это ровно тот обмен, что реализован состояниями `STATE_ADDT_SEND_CMD → STATE_ADDT_WAIT_FE → STATE_ADDT_SEND_DATA → STATE_ADDT_WAIT_DATA_DONE` (`main.c:407-476`) с таймаутами 200/500/1000 мс. Число «1» в `add/cle/addt 1,` — это id кривой `s0` (`ob_page3_s0 = 1` в `V1.4.1.h`).

### 3.2 Экран → STM32

| Байты | Источник в скрипте | Обработка в прошивке |
|---|---|---|
| `55 AA <ch> <state>` | чекбоксы `c0/c1/c2`: `if(c0.val==1){ printh 55 AA 00 01 }else{ printh 55 AA 00 00 }` (и аналогично `01 01/00`, `02 01/00`) | `ProcessTjcRx()`: биты `tjc_visible_flags` 0..2, при включении канала ставит `redraw_queue` |
| `FE` | ответ на `addt` | флаг `tjc_addt_fe_received` |
| `FD` | завершение приёма `addt` | флаг `tjc_addt_fd_received` |

`printh` в языке TJC — вывод шестнадцатеричных байт в UART. Скрипт экрана содержит ровно 8 вызовов:
- `printh 00 00 00 ff ff ff 88 ff ff ff` — при загрузке (page0, строка 7340471 и 7354607) — «приветствие» МК (прошивка его игнорирует, т.к. не `55/AA/FE/FD`);
- 6 вызовов `printh 55 AA <ch> <state>` — события чекбоксов `c0/c1/c2` на page3.

## 4. Логика экрана в скрипте (что делает сам экран)

### 4.1 Экранная клавиатура keybdB (страница 3 в `V1.4.1.h`, id 3)
Универсальная цифровая клавиатура TJC: цифры `b0..b10`, `<`/`>` (`b249/b251`), очистка `b210`, backspace `b200`, ввод `b99`, поле ввода `input`, индикатор `show`, таймер автоповтора `tm0` (`if(tm0.tim==500)`), лимит длины `inputlenth` через `p[loadpageid].b[loadcmpid].txt_maxl2`, возврат на вызвавшую страницу `page loadpageid.val`. Прошивка в этот диалог **не вмешивается** — он полностью автономен внутри экрана (вызывается при нажатии на поле ввода на страницах).

### 4.2 Чекбоксы видимости каналов (page3, id 4)
В `V1.4.1` обработчики чекбоксов **отправляют состояние каналов в МК**:
```
c0: if(c0.val==1){ printh 55 AA 00 01 } else { printh 55 AA 00 00 }
c1: if(c1.val==1){ printh 55 AA 01 01 } else { printh 55 AA 01 00 }
c2: if(c2.val==1){ printh 55 AA 02 01 } else { printh 55 AA 02 00 }
```
Прошивка: `ProcessTjcRx()` обновляет `tjc_visible_flags` и при включении канала ставит бит `redraw_queue` → весь канал перерисовывается через `addt`.

### 4.3 Отличие от `V1.4 .0.HMI` (важно!)
В **V1.4.0** логика была другой — график на экране рисовал **сам экран** через скриптовые переменные:
```
if(c0.val==1){ if(va0.val!=0){ add s0.id,0,va0.val ; va0.val=0 } }
```
(переменные `va0/va1/va2`, таймер `tm0`). В **V1.4.1** этой логики больше нет — остался только `printh 55 AA ...` для чекбоксов, а все данные кривой шлёт **МК командами `add/addt/cle`**. То есть V1.4.1 — это согласованная с текущей прошивкой версия: прошивка сама хранит историю (`graph_history[3][HISTORY_LEN]`), сама масштабирует (`zoom/offset`), сама перерисовывает каналы.

## 6. Замечания и риски

1. **Файл `.HMI` не нужен МК.** МК общается с экраном по UART; `.HMI` — только исходник проекта для USART HMI. Для изменения интерфейса его правят в USART HMI и заливают в экран (`*.tft`). Прошивка STM32 не включает `V1.4.1.h` (в коде его нет — проверено grep'ом), адресация объектов идёт по именам (`x0`, `t9`, `p6`, `s0`).
2. **`V1.4.1.h` — устаревший на 1+ месяц** (24.06) относительно `V1.4.1.HMI` (15.07/19.08). Имена объектов в нём совпадают с извлечёнными из бинарника, но при дальнейшем редактировании экрана заголовок надо перегенерировать (Tools → Generate header).
3. **`page1` vs `page3`:** прошивка обновляет бары `x0..x3` и текст `t9` независимо от активной страницы — команды TJC применяются к объектам на текущей странице. Если пользователь ушёл на page2/клавиатуру, команды для `x0..x3`/`t9`/`p6` экран просто не отрисует (объекты не активны), но `add/addt` для кривой `s0` работают по id и данные накапливаются. Это ожидаемое поведение, но стоит помнить: обновление баров «видно» только на page1.
4. **Приём `55 AA` в прошивке** (`main.c:199-247`) игнорирует всё, кроме `55`, `AA`, `FE`, `FD`, и принимает `state` без проверки `FF FF FF` — совместимо с `printh` (который не добавляет терминатор), но при постороннем шуме на линии возможны ложные переключения каналов.
5. **Дубли таблицы контейнера:** файл содержит две копии таблицы вложенных файлов (0 и 0x80000) — это нормально для формата USART HMI, не ошибка.
6. **Сборка/компиляция:** рабочая копия проекта экрана в папке `Screen\` (`V1.4.1.HMI`), запасные версии `V1.3.HMI`, `V1.4 .0.HMI` и др. — для отката. Текущая прошивка рассчитана именно на V1.4.1 (проверка по разд. 5).
