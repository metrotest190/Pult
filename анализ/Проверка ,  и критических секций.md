# Проверка `portevent.c`, `porttimer.c` и критических секций

## Вывод

В текущем виде порт FreeModbus содержит **две высокоприоритетные ошибки конкурентного доступа**: `xMBPortEventGet()` может потерять событие, опубликованное из ISR, а критические секции не восстанавливают исходное состояние `PRIMASK`. Таймерный порт работает по номинальной частоте 50 мкс, но при повторном включении не сбрасывает счётчик CNT и флаг обновления; из-за этого T3.5 может истечь преждевременно. Также у таймерных функций есть риск линковки из-за внешнего `inline`.

## Очередь событий `portevent.c`

| ID | Место | Проблема | Последствие | Приоритет |
|---|---|---|---|---:|
| E-01 | 29–30 | `eQueuedEvent` и `xEventInQueue` используются из ISR и основного цикла без `volatile` и без критической секции. | Компилятор может оптимизировать доступ к флагу; главное — ISR может записать новое событие между чтением флага в `xMBPortEventGet()` и его обнулением. Тогда новое событие теряется. | Высокий |
| E-02 | 46–50 | Один слот безусловно перезаписывается при каждом `xMBPortEventPost()`. | При двух событиях до обработки сохраняется только последнее; порядок `EV_FRAME_RECEIVED → EV_EXECUTE → EV_FRAME_SENT` может быть разрушен. | Высокий |
| E-03 | 56–67 | Нет проверки `eEvent != NULL`. | Неверный вызов ведёт к HardFault; это не штатный протокольный путь, но проверка почти бесплатна. | Низкий |

Гонка E-01 реальна в следующем порядке: основной цикл входит в `xMBPortEventGet()`, видит `xEventInQueue == TRUE`; затем UART или TIM3 ISR публикует новое событие; после возврата ISR основной цикл записывает `FALSE` в `xEventInQueue`. Только что опубликованное событие исчезает.

Рекомендуется заменить одиночный слот на небольшой FIFO, например на 8 элементов. Очередь необходимо защищать `ENTER_CRITICAL_SECTION()` / `EXIT_CRITICAL_SECTION()`, но только после исправления их реализации в `mt_port.c`. При полном FIFO `xMBPortEventPost()` должен вернуть `FALSE`, а не перезаписывать старое событие.

```c
#define MB_EVENT_QUEUE_LEN 8U

static volatile eMBEventType eventQueue[MB_EVENT_QUEUE_LEN];
static volatile uint8_t eventHead;
static volatile uint8_t eventTail;
static volatile uint8_t eventCount;

BOOL xMBPortEventInit(void)
{
    ENTER_CRITICAL_SECTION();
    eventHead = 0U;
    eventTail = 0U;
    eventCount = 0U;
    EXIT_CRITICAL_SECTION();
    return TRUE;
}

BOOL xMBPortEventPost(eMBEventType eEvent)
{
    BOOL result = FALSE;

    ENTER_CRITICAL_SECTION();
    if (eventCount < MB_EVENT_QUEUE_LEN) {
        eventQueue[eventTail] = eEvent;
        eventTail = (uint8_t)((eventTail + 1U) % MB_EVENT_QUEUE_LEN);
        eventCount++;
        result = TRUE;
    }
    EXIT_CRITICAL_SECTION();
    return result;
}

BOOL xMBPortEventGet(eMBEventType *eEvent)
{
    BOOL result = FALSE;

    if (eEvent == NULL) {
        return FALSE;
    }

    ENTER_CRITICAL_SECTION();
    if (eventCount != 0U) {
        *eEvent = eventQueue[eventHead];
        eventHead = (uint8_t)((eventHead + 1U) % MB_EVENT_QUEUE_LEN);
        eventCount--;
        result = TRUE;
    }
    EXIT_CRITICAL_SECTION();
    return result;
}
```

## Критические секции `mt_port.c`

| ID | Место | Проблема | Последствие | Приоритет |
|---|---|---|---|---:|
| C-01 | 29–45 | `EnterCriticalSection()` всегда включает блокировку IRQ, а `ExitCriticalSection()` всегда вызывает `__enable_irq()` на последнем выходе. Исходный `PRIMASK` не сохраняется. | Если IRQ уже были отключены вызывающим кодом, `ExitCriticalSection()` ошибочно включит их. | Высокий |
| C-02 | 40 | При лишнем `ExitCriticalSection()` счётчик `uint32_t` переполняется в `UINT32_MAX`. | Все последующие выходы перестанут достигать нуля; IRQ могут остаться отключёнными на неопределённое время. | Высокий |
| C-03 | 19 | `lockCounter` не объявлен `volatile`. | Доступ идёт из разных контекстов выполнения; выражение следует защитить и сделать намерение явным. | Средний |

Безопасная реализация должна сохранять исходный `PRIMASK` при самом первом входе и восстанавливать его при последнем выходе.

```c
static volatile uint32_t lockCounter;
static uint32_t savedPrimask;

void EnterCriticalSection(void)
{
    const uint32_t primask = __get_PRIMASK();
    __disable_irq();

    if (lockCounter++ == 0U) {
        savedPrimask = primask;
    }
}

void ExitCriticalSection(void)
{
    if (lockCounter == 0U) {
        Error_Handler();              /* либо assert в Debug */
    }

    if (--lockCounter == 0U) {
        __set_PRIMASK(savedPrimask);
    }
}
```

Эти функции должны оставаться короткими. Внутри критической секции очереди событий допустимы только несколько операций с индексами и памятью; вызовы HAL, ожидания и форматирование строк там запрещены.

## Таймер Modbus RTU `porttimer.c`

| ID | Место | Проблема | Последствие | Приоритет |
|---|---|---|---|---:|
| T-01 | 42–43, 61, 88–90 | `timerCounter` изменяется в основном коде и ISR, но не `volatile`. | При оптимизации возможны некорректные наблюдения значения; намерение совместного доступа не выражено. | Средний |
| T-02 | 59, 68 | Внешние функции определены с `inline`, но объявлены как обычные функции в `mbport.h`. | В зависимости от стандарта С и оптимизации возможна ошибка линковки из-за отсутствующего внешнего символа. | Высокий |
| T-03 | 61–63 | Перед стартом не очищаются CNT, UIF и ожидающий IRQ TIM3. | После stop/start первое прерывание может прийти сразу или раньше требуемых T3.5. | Высокий |
| T-04 | 50–53 | Не проверяются `modbusTimer` и нулевой таймаут. | При неверном порядке инициализации возможны HardFault или таймер, который никогда не истекает. | Средний |
| T-05 | 62, 70 | Результаты `HAL_TIM_Base_Start_IT()` / `HAL_TIM_Base_Stop_IT()` игнорируются. | Ошибка HAL маскируется; стек Modbus ожидает событие, которое никогда не придёт. | Средний |
| T-06 | 86 | `modbusTimer` разыменовывается без NULL-проверки в общем callback HAL. | HardFault при вызове callback до установки модуля или при тестах без инициализации. | Средний |

При конфигурации TIM3 из `.ioc` частота такта таймера равна 72 МГц, prescaler 71 и period 49. Следовательно, период update равен 50 мкс; это согласуется с параметром FreeModbus `usTimeOut50us`. Ошибка в таймере относится к переинициализации и конкурентному доступу, а не к базовой частоте.

Рекомендуемый вариант:

```c
extern TIM_HandleTypeDef *modbusTimer;

static volatile uint16_t timerPeriod;
static volatile uint16_t timerCounter;

BOOL xMBPortTimersInit(USHORT usTimeOut50us)
{
    if ((modbusTimer == NULL) || (usTimeOut50us == 0U)) {
        return FALSE;
    }

    timerPeriod = usTimeOut50us;
    timerCounter = 0U;
    return TRUE;
}

void vMBPortTimersEnable(void)
{
    if (modbusTimer == NULL) {
        Error_Handler();
    }

    ENTER_CRITICAL_SECTION();
    timerCounter = 0U;
    __HAL_TIM_SET_COUNTER(modbusTimer, 0U);
    __HAL_TIM_CLEAR_FLAG(modbusTimer, TIM_FLAG_UPDATE);
    NVIC_ClearPendingIRQ(TIM3_IRQn);
    EXIT_CRITICAL_SECTION();

    if (HAL_TIM_Base_Start_IT(modbusTimer) != HAL_OK) {
        Error_Handler();
    }
}

void vMBPortTimersDisable(void)
{
    if (modbusTimer == NULL) {
        return;
    }

    (void)HAL_TIM_Base_Stop_IT(modbusTimer);
    __HAL_TIM_CLEAR_FLAG(modbusTimer, TIM_FLAG_UPDATE);
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if ((modbusTimer == NULL) || (htim == NULL) ||
        (htim->Instance != modbusTimer->Instance)) {
        return;
    }

    timerCounter++;
    if (timerCounter == timerPeriod) {
        /* The RTU state machine normally stops the timer in this callback.
           Equality also prevents an interrupt storm if a stop operation fails. */
        (void)pxMBPortCBTimerExpired();
    }
}
```

`NVIC_ClearPendingIRQ(TIM3_IRQn)` корректен для данного проекта, где timer port жёстко привязан к TIM3. Для переносимого порта лучше передавать/хранить IRQn отдельно или оставить только очистку `TIM_FLAG_UPDATE` после проверки поведения конкретной HAL.

## Рекомендуемый порядок работ

1. Сначала исправить `mt_port.c`; без этого использовать критические секции в очереди событий опасно.
2. Затем заменить single-slot в `portevent.c` на FIFO и добавить краткие защищённые операции.
3. Убрать `inline`, `volatile`-защитить счётчики и очистить TIM3 перед каждым запуском в `porttimer.c`.
4. На плате проверить три сценария: непрерывные Modbus-запросы, ошибка/перезапуск UART1 и многократный stop/start таймера во время приёма кадров.

> Важно: итоговую валидацию T3.5 необходимо выполнить логическим анализатором. При 115200 бод FreeModbus обычно использует фиксированный интервал T3.5, а не расчёт по каждому байту; реализация `mbrtu.c` определяет точное значение `usTimeOut50us`.
